`unlock.go` is M6 across the binding: `Protect` takes a 32-byte key-encryption key the Android Keystore released after a credential challenge (tier 1), `Unlock`/`Lock`/`LockPeer`/`UnlockedUntil` drive the per-peer session, and `SetOwned` is the local promotion. The split is deliberate — Go holds the sealed key and the timer and can never obtain a credential for itself, Kotlin holds the Keystore and never sees the privilege key.  `OwnedAccess` states this device's protection tier plainly, including tier 3 and "no screen lock", because a user who believes they have unattended access and does not is worse off than one who was told.# Functionality Map

## v2 tree (Go, root module `github.com/shreyashsri79/openair`)
Purpose: OpenAir 2.0. Per D-26 this is one module; `openair-gui` and `oabench` stay separate until v1.0 retires. **M1 (direct transfer), M2 (pairing and trust store), M3 (LAN discovery), M4 (daemon and CLI) and M5 (clipboard) are implemented and work end to end** — two devices pair once, find each other by name, and a file moves between them over QUIC with its SHA-256 matching, with or without a terminal open on the receiving end.

- `cmd/openair` — the CLI. **M4 made it a daemon client**: `pair` and `send` go through `openaird` when one is reachable and fall back to driving a session from this process when it is not (`--no-daemon` forces the fallback). `status` shows what the daemon is doing, `devices` merges its trust store with what discovery can see, and `watch` subscribes to events and answers the daemon's prompts — which is how an inbound transfer gets approved with no GUI. `discover` and `recv` stay direct on purpose: `devices` is the daemon's own view of the same question, and `openaird` replaces `recv` entirely. `daemon.go` holds the client-side plumbing, prompt rendering and event formatting. `pair --listen ADDR` displays an offer and waits; `pair OFFER` consumes one that was scanned or typed. `discover` lists devices on the network and says which are paired. `recv` listens and writes inbound files; `send` dials an explicit `host:port` and offers files. M1's fingerprint prompt is gone from both transfer paths: the trust store answers that question now, and an unpaired device is refused at both ends rather than prompted about. `--yes` still skips the *transfer* prompt on `recv`; there is deliberately no flag that skips the pairing digits (§5.2 forbids one). `send` takes a device name or fingerprint prefix as well as a host:port, resolving it through discovery, and `recv` advertises the port it actually bound while it listens. `main.go` dispatches, `common.go` holds key/trust-store loading, discovery start-up, target resolution and the fingerprint/confirm helpers — the last three now delegate to `discovery.Match`/`discovery.IsAddr` and `identity.DeviceID.Fingerprint` so the daemon and the CLI cannot disagree about which device a user meant. `pair.go`, `discover.go`, `recv.go`, `send.go`, `clip.go` and `daemon.go` are the flows. `clip push DEVICE [TEXT]` sends this machine's clipboard, an argument, or `--stdin`; with no daemon it dials for itself, and `recv` registers the clipboard capability so two daemonless processes can still push to each other. `unlock.go` adds M6's four commands: `protect` creates this device's privilege key (once, against the key directory rather than the daemon, and it says plainly that earlier pairings must be made again), `unlock DEVICE` starts a six-hour session with a prompt that names the device it authorises, `lock [DEVICE]` ends one or all, and `trust DEVICE --owned|--trusted` is §6.4's local act. Passphrases are read without echo from a terminal and from a pipe with `--passphrase-stdin`.
- `cmd/openaird` — the always-on daemon (M4). Flags only: `--listen`, `--dir`, `--keys`, `--socket`, `--name`, `--accept-all`, `--no-announce`, `--quiet`. Everything else is `internal/daemon`. It stops on SIGTERM as well as interrupt, because a service manager uses the former and a daemon killed instead of stopped drops its sessions mid-transfer.
- `internal/rendezvous` — M7, PROTOCOL.md §16. `server.go` is the whole server: one TCP listener, TLS per connection so each learns the client's key from its own handshake, and an in-memory map with no persistence — every entry expires within ten minutes and a device that matters is heartbeating, so a restart costs one interval and the operator has no database to secure. `client.go` registers, heartbeats at two thirds of whatever lifetime the server granted, and looks peers up; a lookup answer is verified against the key already pinned for that device, which is what makes a lying server harmless rather than dangerous. `wire.go` is the framing D-62 defines (§16 specifies none). `endpoints.go` decides what to publish: the bound address when it is specific, every non-loopback interface when the bind is unspecified — publishing addresses a daemon is not listening on would advertise connections that always fail.
- `cmd/openair-rendezvous` — the server binary. It prints the DeviceID clients must pin, and the `--rendezvous host:port@deviceid` line to copy.
- `internal/daemon` — the daemon itself, and the client library the CLI drives it with. `daemon.go` owns identity, trust store, the QUIC listener, discovery and the session registry; `ipcserver.go` answers requests and holds the capability callbacks; `clients.go` is the connected-shell set, the event fan-out and the prompt broadcast; `transfer.go` is outbound send, target resolution and both pairing directions; `client.go` is the shell's end (`Status`, `Devices`, `Send`, `Pair`, `Subscribe`, `Clipboard`, `Unlock`, `Lock`, `Trust`). A live session is reused rather than re-dialled, so a second transfer to the same device costs no handshake. `rendezvous.go` is M7's: it publishes this device's endpoints while the daemon runs and looks a paired peer up when discovery cannot see it, which is the only case where it is consulted at all — the LAN answer wins when there is one. `unlock.go` is M6's surface: unlock and lock per peer, promotion and demotion (§6.4, refused for a peer with no pinned privilege key), the fifteen-minute expiry warning, and `auth.log` in the key directory — one JSON line per authentication event, which is PRD R4's local session log. Demotion ends any live unlock, so withdrawing Owned is not advisory until the timer runs out. An inbound offer from an Owned peer carrying a valid proof is accepted with nobody watching, which is the whole point of the milestone; everything else still needs a human or `--accept-all`.
- `internal/ipc` — the local link: the session envelope (§3) over a unix socket or a Windows named pipe, capID 7 (D-51). `ipc.go` is the symmetric `Peer` — request/response correlation both ways, in two ID namespaces so a prompt cannot collide with a request; `transport_unix.go` and `transport_windows.go` bind and dial; `peercred_linux.go` is the `SO_PEERCRED` check. `peekRequestID` reads `request_id` off the head of a payload without unmarshalling it, which is only sound because the field is number 1 in every daemon message — `TestEveryDaemonMessageHasRequestIDFirst` enforces that against the schema.
- `internal/identity` — two Ed25519 keypairs (D-20). `deviceid.go` derives the DeviceID (§2). `tlsconfig.go` is the D-7 pinning mechanism ported from `oabench/bench/tlsutil.go`: self-signed cert whose key *is* the identity key, raw-public-key comparison, no CA and no hostname check, with ALPN and TLS version re-checked in `VerifyConnection` because Go negotiates an empty ALPN rather than failing when a client offers none. `keyfile.go` is the Appendix A sealed container (XChaCha20-Poly1305 + Argon2id); `truststore.go` is the concurrent-safe persisted store. **M6 made unlock real.** `unlock.go` is D-18's six-hour token as D-19 defines it — the lifetime of the decrypted privilege key in memory, so expiry is a wipe rather than a policy check — scoped per peer by D-30: one unlock authorises one paired device, and `SignOwned` refuses for anyone else. `lockedkey.go` holds the decrypted key in pages pinned by `mlock`/`VirtualLock` (`memlock_unix.go`, `memlock_windows.go`) and zeroes them the moment the last grant lapses; `Swappable()` reports when the kernel refused to pin them, which is a real difference in exposure and is surfaced rather than swallowed. `hardening_linux.go` disables core dumps and marks the process non-dumpable (`hardening_unix.go` does the former only; Windows has no equivalent a process can set for itself). `Operation`/`BeginOwned` are §6.5: new work is refused at expiry, running work continues for at most an hour (D-58). `detect.go` reads the protection tier off the sealed container rather than taking it as configuration (D-60).
- `internal/conn` — dial and accept over one QUIC connection per peer (D-6). `quic_config.go` carries the window and timeout values measured in `oabench`. `DialAddr` pins the peer's key; `Listener` cannot, so it gates callers through the `Authorize` callback instead (D-37). Both install BBR immediately after the handshake (D-36). `Dial` by DeviceID returns a not-implemented error — that is Phase 2.
- `internal/session` — `envelope.go` is the 8-byte frame (§3), validating version and length *before* allocating so an 8-byte header claiming 4 GiB costs the receiver nothing. `session.go` is the concrete `Session`: control stream, Hello exchange (§4), capability negotiation, and dispatch through one bounded queue per capability (D-41). `convert.go` holds every wire↔domain conversion in one place (D-34, D-39). `auth.go` is §6's gate, added by M6: it verifies an inbound `AuthProof` against the peer's *pinned* privilege key, checks the ±60s window and the nonce cache, and spends the proof on the one message it authorises (D-57). The decision is made on the control loop before the message is queued, and travels with it — `OwnedFromContext` is how a capability tells "a Trusted peer is asking" from "an unlocked Owned peer is asking" for the same message. `Config.PeerLookup` is what gives the *accepting* side the pinned privilege key and trust level, which Hello cannot carry; `Config.OnAuthEvent` is the hook the daemon's session log hangs on (PRD R4, §6.3). `SendOwnedIfUnlocked` is the initiating half: an ordinary message is upgraded with a proof when this device has a live unlock for the peer, and sent plainly when it does not. `testdata/envelope_vectors.json` + `golden_test.go` are the hand-derived golden vectors (HLD §5).
- `internal/caps/files` — the `files` capability (capID 1). `plan.go` distributes chunks by atomic counter and validates inbound frames; `framing.go` is v1.0's 12-byte chunk header; `send.go` and `recv.go` are the two sides; `state.go` persists the verified-chunk bitmap for resume; `path.go` refuses traversal before any filesystem call is made.
- `internal/pairing` — PROTOCOL.md §5 (pairing), §6.1 (revocation) and §6.4 (grants), all on capID 0. `offer.go` is the out-of-band offer: one base32 string carrying the DeviceID, a 16-byte fingerprint and LAN hints, printed as `openair://pair/...` for a QR and hyphenated for typing; `VerifyOffer` checks the key the peer presented in TLS against the scanned fingerprint, which is what authenticates the offering device. `sas.go` derives the six digits both users compare — see D-45 for the three things §5.2 left unstated. `pairing.go` runs the exchange (`Initiate` scanned-and-dialled, `Await` displayed-and-accepted); it binds the identity key in every pairing message to the key that terminated TLS, so a claimed key can never be the one that gets pinned. `authorize.go` is the trust-store gate that replaces M1's nil `session.Config.Authorize`, plus the pairing window that is the *only* thing admitting an unpaired peer. `guard.go` is §6.1's mid-session enforcement point: a live session consults it per operation, so a revoke lands on work already in progress.
- `internal/congestion` — BBR, vendored from Hysteria (D-35) and installed on live connections through the apernet fork's public `SetCongestionControl`. `PROVENANCE.md` records the upstream, the two local modifications and the re-sync procedure. Default gain profile is conservative (D-36).
- `internal/discovery` — LAN discovery (PROTOCOL.md §15). `mdns.go` is §15.1 over `_openair._udp` — note the `_udp`, since v2 is QUIC and a v1.0 device on `_tcp` is deliberately invisible. `unicast.go` is §15.2's fallback for networks that filter multicast: a UDP beacon on port 53318 carrying query and announce datagrams, answered unicast to the asker so discovery converges in one round trip rather than one beacon interval. `announce.go` holds the single record shape both transports carry, the fallback's byte layout, and address ranking (routable before link-local before loopback). `discovery.go` merges both into one event stream with a TTL sweep. **It never dials** — its whole output is candidates, and keeping it apart from the connection manager is what stops an unauthenticated broadcast from causing an outbound connection. `BrowseOnly` listens without announcing, for processes that have no listening port to advertise.
- `internal/caps/clipboard` — the `clipboard` capability (capID 2, §9). `clipboard.go` is the capability: one message type, text only for now, capped at 1 MiB and refused rather than buffered past it, invalid UTF-8 refused because the MIME type names a charset. It runs on the **identity key, not the privilege key** (D-20) — `TestRunsOnTheIdentityKey` pins that, because raising it to Owned would stop the clipboard working whenever an unlock expired. `os.go` reaches the system clipboard by exec'ing the desktop's own helper (D-54), and reports `ErrNoClipboard` where there is none, which is a normal condition rather than a failure. Echo suppression by `origin_tag` is already implemented, so M13 does not have to re-derive the rule.
- `proto/openair/v1/daemon.proto` — the daemon control plane's message set (D-51). Local only; not part of the interoperable protocol, though Appendix B reserves its capID so a future network capability cannot take it.
- `mobile/` — the gomobile-bindable façade (D-10, D-31). `clipboard.go` is M5 across the binding: `Clipboard.Push` dials, checks the trust store against the key the peer presented, and pushes; `Receiver.SetClipboard` registers the receiving half, which is opt-in so a shell that never calls it is not reachable on capID 2 at all. It is at the repo root rather than under `internal/` because `gomobile bind` cannot bind an internal package. `identity.go` opens the keys and the trust store; `pairing.go` runs §5 from either side behind an `SASVerifier` the shell must implement; `discovery.go` browses and returns an indexable `DeviceList`; `sender.go` and `receiver.go` are the two transfer paths, both gated on the trust store. `doc.go` states the gobind subset the API has to stay inside — no unsigned ints, no slices but `[]byte`, no maps or channels, callbacks as interfaces — which is why lists are objects with index accessors.
- `internal/wire` — generated protobuf, committed (D-28).
- `internal/{identity,session,caps,conn}/types.go` — the shared Phase 1 contracts (`DeviceID`, `Identity`, `TrustStore`, `Envelope`, `Session`, `Stream`, `Capability`, `Dialer`). Defined ahead of implementation so parallel agents could not invent incompatible boundaries; they survived wave 1 with one addition (`Config.Authorize`, D-37).

Control flow, `send` to `recv`: dial → QUIC/TLS handshake with the peer's raw key pinned (or unpinned at M1) → install BBR → open the control stream and exchange Hello → `Authorize` gates the peer → offer (`TransferOffer`) → receiver accepts and returns any verified-chunk set for resume → manifest of per-chunk digests → **two** data streams (never eight — D-13, D-33) carrying raw 12-byte-header frames → receiver verifies each chunk against the manifest *before* writing → rename `.oapart` into place → `TransferComplete`.

Sharp edges:
- **A chunk offset is transfer-global across the offered files concatenated in offer order, and chunks never span a file boundary** (D-40). PROTOCOL.md §8.3 does not say this yet and needs the amendment — it is wire-visible.
- Two data streams by default. `TestDefaultStreamCountIsTwo` exists to stop v1.0's eight coming back.
- A receiver verifies before writing, so corrupt bytes never reach the destination file. `Plan.Locate` doubles as an authorisation check: without it a peer granted `files` could write arbitrary bytes at an arbitrary offset by lying in a 12-byte header.
- `conn.Listener.Accept` no longer runs Hello inline (D-52): a pump goroutine accepts QUIC connections and hands each Hello to its own goroutine, 32 in flight at most, 10 s each. A failed handshake arrives as a `*conn.HandshakeError`, which callers must log and continue past — treating it as terminal is how a stranger stops a device listening. Only `ErrListenerClosed` and listener-level failures end the loop.
- A nil `session.Config.Authorize` still admits every peer — the type permits it. Nothing in `cmd/openair` passes nil any more (M2 wires `pairing.Handler.Authorize` on every path), but the hazard is now that a *future* caller can forget to, and the compiler will not say so. Making it non-optional on the listening path is still owed.
- The daemon's IPC socket is a **local trust boundary**, not hygiene: anything that opens it drives the daemon with this device's identity key. Enforcement is a 0700 directory, a 0600 socket and an `SO_PEERCRED` uid check on Linux; an owner-only SDDL on the Windows pipe. On the BSDs and macOS the credential check is not wired up yet and the file permissions stand alone.
- With no subscribed client able to answer and no `--accept-all`, an inbound transfer is **refused**, not queued (D-53). `openair status` says so in as many words when that is the state.
- Putting content into a system clipboard means a subprocess (D-54), and `wl-copy` forks a child that holds the selection until something replaces it. Give that child an `os/exec` pipe for stderr and `cmd.Run` never returns; `internal/caps/clipboard/os.go` uses a real file and a `WaitDelay`, and the daemon runs the write off the capability queue so a helper cannot stall the peer's later messages.
- **Per-peer unlock scope is policy, not cryptography** (D-30). One decrypted privilege key can sign for any peer; what bounds it is this daemon's own bookkeeping. D-30 records the delegation design that would make it cryptographic and deliberately does not adopt it.
- An `AuthProof` is spent by the *next* message that verifies against it (D-57). That works because the control stream is ordered; it does **not** extend to a capability that opens its own stream, since QUIC does not order a new stream against the control stream. No Phase 1 capability requires Owned, so nothing exercises the gap, and a capability that does will need its proof on its own stream.
- §6.5's one-hour grace is enforced on the initiator only (D-58), because the wire carries no expiry for a verifier to compute it from. A compromised initiator ignoring its own timer keeps work it already started; it cannot start more.
- The unlock credential crosses the IPC socket (D-59), so it exists in two processes rather than one. The daemon zeroes and unlocks the *key*'s pages on expiry; the request payload carrying the passphrase is not zeroed.
- Linux runs on tier 2 despite having a TPM (D-61). Sealing to the TPM is two implementations — PCR-bound for always-on, user-presence for interactive — and is not done, so the maintainer's own machine is on the branch D-19 called the weaker one.
- A refused peer is closed with `NOT_PAIRED`, not `PROTOCOL_VIOLATION`, and `conn.DialAddr` translates a remote close back into a `session.ProtocolError` so callers can explain it (D-55). The consequence is that an unpaired send now fails at the far end's Hello, before the sender's own trust-store check runs.
- The daemon keeps one session per peer and reuses it. `session.Session.Done()` is what makes a dead one leave the registry; before it existed the only way to notice was to send something and watch it fail.
- **A message that ends the conversation must not be followed straight by a close** — `CONNECTION_CLOSE` overtakes unflushed stream data and the peer never sees it (D-46). `internal/pairing` lingers 250 ms; the general fix is a flush-then-close on `session.Session`, still owed — M4 did not need it, because the daemon's own conversation-enders (a refused transfer, a `TransferComplete`) are answered on a session that stays open.
- A discovery candidate is an unauthenticated hint and nothing more. A matching DeviceID does **not** mean the device at those addresses holds the key for it — `TestHostileAnnounceCannotRedirectASession` is the proof, and the pinned-key TLS handshake is what actually decides.
- `send` tries a discovered device's addresses in order, but stops dead on a key mismatch rather than trying the next one: the other addresses belong to the same impostor.
- The Android `.aar` is per-ABI and about 7 MB each; `libgojni.so` lands at ~10 MB in the APK. Build the ABIs you need (`OPENAIR_AAR_TARGETS`), not all four.
- Pairing admits an unpaired peer only while a window is open, and windows nest. A UI that opens one and forgets to close it leaves the device pairable indefinitely — `pair --listen` scopes it to the life of the command.
- `identity.ProtectionTier` runs 0/1/2 with `TierNone` first, while the wire runs 1/2/3 in the opposite order. Convert, never cast — a cast downgrades a keystore-backed peer to unprotected (D-39).
- `send` reads each source file twice: once for the offer and manifest digests, once to transmit. §8.4 permits a single pass by sending the manifest during the transfer, at the cost of buffering unverified chunks. Deliberate.
- The privilege *public* key lives in a `privilege.pub` sidecar because Appendix A has no field for it (D-42).

Purpose: the versioned wire format, spec-first per HLD principle 4. Covers all four phases: envelope, session establishment, pairing, authorisation and flow control; `files` and `clipboard` (Phase 1); discovery, rendezvous, relay and connection establishment (Phase 2); `remotefs` and `notifications` (Phase 3); `input` and `mirror` (Phase 4). Section 14 (`mirror`) is provisional pending D-9. Where code and this file disagree, the spec is right and the code is a bug.

**Nine outstanding edits**, all found by implementing Phase 1 and worked around rather than fixed. M2 added four: §5.2 never states that the pairing transcript sorts both key pairs by value, gives no encoding for a tier-none device's absent privilege key, and is ambiguous about which nonce comes first (D-45); and §6.4's prose still carries its own trust scale where the schema now uses the shared `TrustLevel` enum. The five from wave 1: §8.3 must state that a chunk offset is transfer-global across concatenated files (D-40) — this one is wire-visible and urgent. §3 and §10 disagree on the error code for an unknown envelope version (D-38). §3's "every enum is offset by one" is wrong for `msgType` and `ProtectionTier` (D-39). Appendix A needs a field for the privilege public key (D-42). §17's `RelayAuth` needs domain separation and a binding to the relay's identity (D-43). Two more places are underspecified rather than wrong: §6's `AuthProof` signing input gives no widths or endianness, and §2 never states that the handshake is mutually authenticated — a responder following it literally leaves the initiator unauthenticated, which §6's model assumes cannot happen.

## oabench (Go) — v2.0 transport spike
Purpose: measure whether a single QUIC connection with N streams can match v1.0's N-parallel-TCP engine, and at what CPU cost. Exists to settle PRD risk K1 / ADR-1 **before** the v2 stack is built on QUIC. Own Go module (`github.com/shreyashsri79/openair/oabench`); does not import or affect `openair-gui`.
- `main.go` — `serve` / `send` subcommands, flag parsing, stream-count sweep, median-of-N.
- `bench/framing.go` — v1.0's 12-byte chunk header (`int64` offset + `int32` size, little-endian), role tags, session preamble. Deliberately byte-identical to v1.0 so the measurement isolates transport, not framing.
- `bench/plan.go` — lock-free chunk distribution (atomic counter replaces v1.0's jobs channel) and payload generation.
- `bench/transfer.go` — `Config`, shared send loop, and the sink (discard, or `WriteAt` reconstruction).
- `bench/tcp.go` — v1.0-shaped baseline: N independent TCP connections.
- `bench/quic.go` — v2.0-shaped candidate: one QUIC connection, N streams, per HLD "one connection per peer".
- `bench/tlsutil.go` — Ed25519 identity, self-signed cert, `VerifyPeerCertificate` pinning. Doubles as the ADR-2 dry run.
- `bench/latency.go` — interactive-latency probe: request/response ping sampled idle then during the transfer, reported as percentiles. `probeIdle` / `startBusyProbes` / `finishBusyProbes` orchestrate the two phases; `streamPing` and `echoStream` are transport-agnostic, `datagramPing` and `echoDatagrams` live in `quic.go`.
- `bench/cpu_linux.go` / `cpu_other.go` — `getrusage` CPU accounting; no-op off Linux.
- `netem/lab.sh` — runs a command in an unprivileged user+network namespace with `tc netem` applied to a 1500-MTU loopback. No root needed.
- `netem/run-one.sh` — one profile's sweep: TCP, then QUIC with GSO on, then GSO off.
- `netem/matrix.sh`, `netem/report.sh` — full matrix runner and the gate pivot table.

Control flow (both transports): sender opens a control channel, sends `preamble{total, streams, chunk, flags}`, waits for a go-ahead, then opens N data channels. With `-probe`, a ping channel is opened *before* the go-ahead — a QUIC stream on the same connection as bulk, or for TCP a separate connection, mirroring v1.0's architecture. That asymmetry is the measurement, not an oversight (D-17). Timer starts once all channels are up and stops when the **receiver** acks completion on the control channel — stopping at the last `Write` would measure the kernel send buffer, not delivery. On QUIC the receiver must drain the control stream to EOF before closing the connection, because `CONNECTION_CLOSE` preempts undelivered stream data and would race the ack away.

Sharp edges:
- `bench/tlsutil.go` uses a **fixed Ed25519 seed** so the client can pin the server with no out-of-band exchange. Spike only; must not reach the daemon.
- Timing is only meaningful under `netem/lab.sh`. Unshaped loopback reports ~38 Gb/s for TCP.
- Sender, receiver and netem share one CPU, so results are pessimistic for the CPU-hungrier transport (QUIC) and become CPU-bound rather than link-bound at gigabit rates. Two-machine runs are needed before ADR-1 is settled.
- `QUIC_GO_DISABLE_GSO=1` was originally used as a Linux proxy for the Windows send path. Per D-13 it is not a proxy: quic-go's `UDP_SEGMENT` support is Linux-only by construction, so GSO-off *is* Windows and macOS behaviour.
- netem queue depth is derived from the bandwidth-delay product, `BUFFER_BDP` multiples, default 4. It was previously a flat 100000 packets, which was extreme bufferbloat and made latency-under-load meaningless; see D-17. Always state the buffer depth when quoting latency figures.
